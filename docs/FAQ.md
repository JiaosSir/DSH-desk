## 安装与启动

### 安装时被 SmartScreen 拦截怎么办

v1 安装包**未做代码签名**，Windows SmartScreen 提示「Windows 已保护你的电脑」是预期行为，按以下步骤继续：

1. 在提示窗口点击 **「更多信息」**；
2. 点击 **「仍要运行」**；
3. 若弹出确认，选择 **「是」**。

便携版同理：若解压后的 `dsh-desk.exe` 被拦截，按上述步骤操作，或右键该文件 → **属性** → **解除锁定** → 确定。

> 安全说明：本应用开源（MIT），安装包由 CI 从源码自动构建后上传 GitHub Releases，仅此一个下载渠道；你也可以从源码自行构建（[BUILDING](dev/BUILDING.md)）。

### 首次启动卡在等待页 / 提示网络失败

首次启动做两件事：**本地解压引擎**（不需要网络）与**初始化插件配置**（需要访问 npm registry 下载插件依赖）。

- **一直显示「正在准备本地环境…」进度条**：首次解压 sidecar 需要 0.5–2 分钟（取决于磁盘与杀软扫描），请耐心等待；若长时间无进展，按下面「日志在哪」打开日志目录查看进度与报错。
- **插件初始化失败（网络问题）**：**不会阻塞启动**——初始化是幂等的，网络不可用时仅跳过桥接插件（宿主与 Web UI 照常可用，只是设置区没有「桌面」分区），日志会记录失败原因；网络恢复后**重启应用**即自动补装。
- 反复失败（解压/启动层面）时：打开日志目录，把 `shell-*.log` 与 `sidecar-*.log` 的最新内容发给开发者（见[日志在哪](#日志在哪怎么给开发者)）。

### 提示缺少 WebView2 怎么办

DSH-desk 的界面依赖微软 WebView2 Runtime（Windows 11 自带；Windows 10 需单独安装）。

- 安装器在检测到缺失时会自动引导安装（需要网络，一次性）；
- 若引导失败，可手动从微软官网下载安装 **Evergreen WebView2 Runtime**（`https://developer.microsoft.com/microsoft-edge/webview2/`），装完重开应用即可；
- 安装成功后错误页消失，正常进入主界面。

### 提示端口被占用

应用每次启动会为本机 Harness 服务**自动挑选空闲端口**，一般不会冲突；若提示端口相关错误（或安全软件拦截了本机回环监听），请：

1. 检查是否有其他程序大量占用端口，或安全软件拦截了 `127.0.0.1` 回环流量；
2. 在错误页点 **「重试」**（会换端口重试）；
3. 仍失败则查看日志定位具体报错（日志里会写明被拒的原因）。

### 被杀毒软件或防火墙拦截（误报）

未签名的应用容易被安全软件误报。DSH-desk 开源、零遥测，出站流量清单见[根 README](../README.md#隐私与网络)：

- 若杀软提示拦截，选择「允许」并**反馈误报**给对应厂商（提供 SHA-256 校验值）；
- 若防火墙拦截，放行 `dsh-desk.exe` 即可——它只需要监听本机 `127.0.0.1`，并访问 `api.deepseek.com`（模型调用）与 `registry.npmjs.org`（插件安装）；
- 便携版建议从官方 Releases 下载后核对哈希，避免第三方转发的包。

## 使用

### API key 填在哪？存到哪里？

首次进入会在**页面内**引导填写 DeepSeek API key：前往 [DeepSeek 开放平台](https://platform.deepseek.com) 创建（形如 `sk-…`），粘贴保存即可。

- key 写入 `~/.dsh/.credentials.yaml`（受管凭据文档，`0600` 权限；尊重 `DSH_HOME` 环境变量），与 CLI 版 dsh 使用**同一凭证机制**，两边互通；`~/.dsh/.env` 里已有的旧 key 仍会被读取（回退层），但新写入一律进凭据文档；
- 桌面壳只检测「是否已配置」（已有则跳过引导步骤），**不读取、不上传** key 内容；
- 换 key：在应用内设置页重新填写保存（覆盖凭据文档），或编辑 `~/.dsh/.credentials.yaml` 后重启应用。

### 桌面版和 CLI 版 dsh 能一起用吗

可以。两者共享 `~/.dsh` 用户数据（profile、会话、凭证、插件），桌面版**永远使用随包自带的引擎**，不会动你系统里安装的 dsh；两边可同时安装、随时切换，数据无缝衔接。

两点注意：

- **建议保持同一 rc 版本**（当前 `0.1.1-rc.2`）。两边的插件依赖树共享同一个 profile 目录，版本差异过大时，profile 的依赖回退链接以「**最后一次启动的安装**」为准（last-writer-wins）——来回切换可能触发依赖重装，属预期行为，重启应用即可自动修复。
- 不要在桌面版运行期间同时用 CLI 版操作**同一个 profile** 的插件安装，避免交错写入。

### 新装的插件不生效

插件（含社区插件）装好后需要**重启宿主**才生效：

- 在设置区「桌面」分区点 **「重启宿主」**（或托盘菜单「重启宿主」）；
- 提示文案「新装插件在宿主重启后生效」指的就是这一步。

插件安装本身走 Harness 标准的 `dsh plugin` 机制（npm registry），与网页版完全一致。

### 快捷键冲突了怎么改

缺省全局快捷键为 `Ctrl+Alt+D`（唤起/隐藏窗口），设置区「桌面」分区会展示当前值（v1 只读，改键 UI 后续版本提供）。手动修改：

1. 关闭 DSH-desk；
2. 编辑 `~/.dsh/desktop/config.json`（尊重 `DSH_HOME`，即 `$DSH_HOME/desktop/config.json`）：

```json
{
  "hotkey": "Ctrl+Shift+D",
  "autostart": false
}
```

3. 保存后重新启动应用。

说明：格式参照 Tauri 快捷键写法（`Ctrl` / `Alt` / `Shift` + 单键）；**非法值自动回退**为 `Ctrl+Alt+D`，不会导致启动失败。

### 关闭窗口后应用还在后台吗

不会。关闭窗口 = 退出应用（同时停止本机 Harness 服务），不留后台进程；托盘驻留模式属于后续版本规划。如需后台常驻，可在设置区开启**开机自启**（仅登录 Windows 时自动启动，与驻留无关）。

### 页面和网页版长得不一样 / 功能缺失

不会。桌面端加载的就是 Harness **同一份 Web UI**（由随包引擎在本机 `127.0.0.1` 提供），与网页版功能完全一致；桌面端只是在浏览器里额外注入了「桌面」设置区与通知镜像，缺了桥接能力的纯浏览器打开同一地址时，这些桌面专属项自动隐藏，其余功能不变。

## 数据与故障排查

### 日志在哪？怎么发给开发者？

滚动日志（壳 1MB×2、sidecar 1MB×2）位于：

```
~/.dsh/desktop/logs/          # 尊重 DSH_HOME：$DSH_HOME/desktop/logs/
├─ shell-YYYYMMDD.log         # 壳事件：启动、就绪、重启、失败原因
└─ sidecar-YYYYMMDD.log       # sidecar 原始输出（含报错堆栈）
```

打开方式：托盘菜单或错误页的 **「打开日志目录」**。

报 Bug / 反馈问题时，请附上**当天**这两个日志文件（可先删除敏感信息，如 API key 片段），并在问题描述里说明：操作步骤、复现时机、DSH-desk 版本（错误页或关于页可见）。

### 为什么磁盘占用这么大

应用随包自带完整 Node 运行时与钉版 Harness 依赖树（sidecar），保证「不装 Node、双击即用」：

- 安装包约 55MB（sidecar 以单个归档压缩分发），**安装后** sidecar 解压到本地缓存约 320MB；
- 缓存位置：`%LOCALAPPDATA%\com.dsh.desk\sidecar-dist`（环境变量 `DSH_DESK_SIDECAR_CACHE` 可覆盖）；
- 引擎版本不变时缓存复用，升级版本会自动刷新（旧版本缓存会被清理）；
- 想彻底腾空间：卸载应用后删除 `%LOCALAPPDATA%\com.dsh.desk\` 与 `~/.dsh`（会同时删除个人数据，请先备份）。

### 升级会不会丢数据？怎么备份？

不会。升级 = 下载新版安装包**覆盖安装**，`~/.dsh` 中的 profile、会话、凭证**原样保留**；升级后首次启动自动刷新引擎版本。

手动备份（迁移到新电脑也用得上）：复制整个 `~/.dsh` 目录即可（注意 `.env` / `.credentials.yaml` 是明文凭证，请妥善保管）。

### 怎么知道有没有新版本？

应用**不做任何自动更新检查**（零遥测、零后台请求）。想看新版本：

- 设置区「桌面」分区 → **「查看最新版」**：在系统浏览器打开 GitHub Releases 页面，由你主动查看；
- 或直接访问 <https://github.com/JiaosSir/DSH-desk/releases>。

### 不用桌面端，直接用浏览器打开可以吗

可以。桌面端启动的 Harness 服务监听本机 `127.0.0.1` 的随机空闲端口，用浏览器打开同一地址即可获得**等价功能**（无桌面专属项：托盘、快捷键、通知、开机自启——这些由桌面壳提供，浏览器里自动隐藏）。就绪地址记录在 `~/.dsh/desktop/logs/shell-*.log`（「宿主就绪: http://127.0.0.1:<port>」行）。

> 说明：正常使用请从桌面应用进入；直接用浏览器打开仅适合排查「是不是桌面壳的问题」这类场景。
